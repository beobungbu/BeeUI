# BeeUI R10 consumer starters

Four minimal, real, buildable consumers dogfooding BeeUI's two distribution
models ([ADR-011](../docs/decisions/011-distribution-architecture.md)):

| Starter | Issue | Model | Toolchain |
| --- | --- | --- | --- |
| [`expo-package-consumer/`](expo-package-consumer/) | [#230](https://github.com/beobungbu/BeeUI/issues/230) | Centralized package consumption | Expo SDK 57 / Metro |
| [`source-ownership-starter/`](source-ownership-starter/) | [#231](https://github.com/beobungbu/BeeUI/issues/231) | Source ownership (`beeui add`) | Vite + react-native-web |
| [`bare-rn-consumer/`](bare-rn-consumer/) | [#232](https://github.com/beobungbu/BeeUI/issues/232) | Centralized package consumption | Bare React Native / Metro |
| [`web-consumer/`](web-consumer/) | [#233](https://github.com/beobungbu/BeeUI/issues/233) | Centralized package consumption | Vite + react-native-web |

These are intentionally **minimal starters**, not polished demo apps — the
production demo is tracked separately (#236/#258–263). Each one proves a
distinct, real consumption path builds cleanly; none of them are a
substitute for the full Showcase.

Alongside the starters, [`agent-reference-app/`](agent-reference-app/)
([#235](https://github.com/beobungbu/BeeUI/issues/235)) is a small reference
*application* (an "Access Requests" console) built **only from BeeUI's
AI-agent-facing context** (the `llms.txt` family + `docs/ai-agent-cookbook.md`),
to validate that those docs are enough for a fresh agent to build a real BeeUI
app. Its [`AGENT-BUILD-NOTES.md`](agent-reference-app/AGENT-BUILD-NOTES.md)
records the doc gaps found along the way. It consumes the same `pnpm pack`
tarball boundary as the Web starter.

## Unpublished status (read this first)

BeeUI is **not published to npm**. Per ADR-011's owner guard, no package or
CLI is published until the owner explicitly commands the BeeUI 1.0 release
(#254). Every starter here therefore consumes BeeUI through real `pnpm pack`
tarballs — the exact same package boundary `scripts/verify-bare-consumer.sh`
and `scripts/verify-web-consumer.sh` already prove in CI — never a
`workspace:*` link and never a hand-copied `dist/` folder. `examples/scripts/pack-beeui-packages.mjs`
is the small shared helper every starter's `setup.sh` calls to do this.

None of these starters are registered in the root pnpm workspace
(`pnpm-workspace.yaml` is untouched): each one installs its own dependencies
with plain `npm install`, isolated from the monorepo, matching the existing
clean-consumer verification scripts' "no monorepo fallback" rule. This also
means `pnpm typecheck`/`pnpm build` at the repo root do not touch them at
all.

## Running a starter

From the repo root, first build the packages once:

```sh
pnpm build
```

Then, inside any starter directory:

```sh
bash setup.sh    # packs BeeUI tarballs, npm installs everything
bash bundle.sh   # or: npm run build (web-consumer / source-ownership-starter)
```

See each starter's own README for exact commands and acceptance evidence.

## Scope note

`bare-rn-consumer/app/` and the Expo starter's Metro/Vite build output are
generated by `setup.sh`/`bundle.sh` and are gitignored — they are
mechanically reproducible from the pinned CLI/RN versions and the committed
source in each starter, exactly like `node_modules/`. `source-ownership-starter/`
is the deliberate exception: its `beeui add`-copied files (`src/components/beeui/`,
`src/lib/beeui/`, `src/beeui/theme.css`, `beeui.config.json`) **are** committed,
because that is what source ownership means — the consumer owns and versions
those files, not a build script.
