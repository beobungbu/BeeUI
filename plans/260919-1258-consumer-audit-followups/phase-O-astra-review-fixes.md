Owned: packages/ui/src/components/{toolbar,table,table.web,table-shared,sheet.native}.ts(x), apps/showcase/__tests__/**, apps/visual-regression/tests/** (+ App.tsx fixtures), examples/web-consumer/src/**, scripts/verify-web-consumer.sh, and the Table/Toolbar docs pages under apps/docs/src/content/docs/components/ only for the contract sentences below (regenerate via `pnpm docs:portal-pages:generate`, never a single generator script). Do NOT touch docs/dist-tag-policy.md (handled separately).

1. Toolbar roving focus (major). `sequence` in toolbar.tsx currently lists every visible `ToolbarItem` whether or not its child rendered a focusable; `withRovingFocus` returns null/text unchanged and clones a Fragment. Fix: derive the roving sequence only from items whose cloned child actually registered a focus function (focusablesRef), so null/text/conditional children are skipped and the sole `tabIndex=0` always lands on a real control; treat `React.Fragment` and non-element children as non-focusable and warn once in dev. Tests: null child, conditional child, Fragment child, plain non-BeeUI element child, disabled child, overflow trigger still last.

2. TableRow onPress embedded-action contract (major). Web (table.web.tsx ~457-470): the `<tr>` gets `onClick: onPress` with no exclusion, so a click on a checkbox/button/link inside a cell also activates the row. Fix: ignore row activation when `event.target` sits inside an interactive descendant (`button, a[href], input, select, textarea, [role=button], [role=checkbox], [role=link], [role=switch], [role=menuitem], [contenteditable]`) other than the row itself; same guard for the Enter/Space key path. Native (table.tsx ~324): the row is a `Pressable accessibilityRole="button"`; RN's responder gives the inner Pressable the touch, so embedded buttons keep working — add a test proving a nested Button press does not call the row's onPress, and document the a11y rule on the Table page: a row with `onPress` should not embed interactive controls on native (screen readers expose the row as one button); prefer a cell action or a leading checkbox with `onPress` only on web. Tests on Web: click nested Button / Checkbox → row onPress not called; click plain cell → called; Enter on nested button → row not called.

3. #550/#552 package-boundary proof (minor). examples/web-consumer/src/App.tsx does not render `BeeThemeScope` or read `useBeeToken`. Add a fixture: a `BeeThemeScope` with a different brand/appearance wrapping a tokenized element plus a `useBeeToken` readout inside and outside the scope; extend scripts/verify-web-consumer.sh to assert the computed semantic CSS variable and the `useBeeToken` values differ inside vs outside (this script runs in the web-consumer CI workflow against the packed tarballs). Keep the visual-regression spec as is.

4. Sheet rapid close→reopen (plausible). sheet.native.tsx `handleDismiss` resets `presentedRef` and then checks `openRef.current`; if the caller toggled open=true→false→true before gorhom's asynchronous `onDismiss` returned, the late callback may treat the reopen as a fresh dismissal. Write a deterministic jest test with the gorhom mock: open → close → open, then fire the pending onDismiss; the sheet must end presented and `onOpenChange(false)` must not be emitted for the reopen. Fix the state machine if the test fails (e.g. a presentation generation counter so a stale onDismiss is ignored). Also add the rapid-toggle case to the iOS Maestro flow wired by WS-L.
