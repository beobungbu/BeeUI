# WS-P · regressions introduced by #617, fixed on fix/consumer-audit-batch

Source: plans/reports/from-astra-260920-1827-deep-review-report.md items 1, 2, 5 (read it on branch fix/consumer-audit-followups: `git show fix/consumer-audit-followups:plans/reports/from-astra-260920-1827-deep-review-report.md`).

Owned: packages/ui/src/components/{input,password-input,safe-area,icon-button}.tsx, apps/showcase/__tests__/**, apps/visual-regression/tests/** if a browser proof is needed. Do NOT touch toolbar.tsx, table*.tsx, sheet*.tsx, docs pages, or dist-tag policy (other workstreams).

1. Input / PasswordInput accessibility value (item 1). `input.tsx` fills `accessibilityValue.text` with the current text whenever an accessibility label is present. Never do that when `secureTextEntry` is true (masked field): omit the automatic text; a caller-supplied `accessibilityValue.text` still wins. Tests: `<Field label="Password"><PasswordInput value="secret123" /></Field>` masked → no `accessibilityValue.text`; after the show toggle (unmasked) → value exposed; plain labelled Input unchanged.
2. SafeArea (item 2). Today a padding utility in `className` (even a variant-prefixed one like `md:pt-6`) removes the matching edge from `edges`, so the device inset disappears. Redesign so inset and caller padding compose additively: keep `edges`/insets fully owned by react-native-safe-area-context on the outer element and apply the caller's `className` (and `style`) padding on an inner wrapper View that fills the safe box (only when the className/style actually carries padding; otherwise render as today with no extra node). Remove the padding-detection edge stripping and its regex. Tests must assert final geometry with a non-zero inset (mock insets top=47, className `pt-6` → outer padding 47, inner padding 24; `md:pt-6` never removes an edge), plus a no-padding case rendering a single node. Update the SafeArea docs text in your report (docs page is owned elsewhere).
3. IconButton (item 5). Render the `Button` directly when `count` is undefined (restore the pre-#617 layout root, so `className="flex-1"`/`self-center`/`style` keep working). Only with `count` render the badge overlay, and make the overlay wrapper transparent to layout (forward `className`/`style` to the wrapper so the consumer's layout props still apply to the outermost node; document this). `size="sm"`: guarantee a 44dp tappable region in both dimensions on native (`ios:min-w-touch-target android:min-w-touch-target` alongside the existing min-h) and test both. Custom-node `count`: either drop `aria-hidden` on the badge container when the node is a custom element and let it carry its own accessible text, or change the docs claim; pick one and test it.
