Items (read each issue with `gh issue view N --repo beobungbu/BeeUI`):

1. #591 closable, scrollable tab strip (POS open orders). Extend the existing Tabs family rather than adding a new one:
   - `TabsList scrollable?: boolean` → horizontal ScrollView on native, overflow-x auto with keyboard/arrow navigation preserved on web; the selected tab scrolls into view on change.
   - `TabsTrigger closable?: boolean` + `onClose?: (value) => void` rendering an accessible close control (role button, accessible name "Close <tab label>" via prop `closeAccessibilityLabel`, no hardcoded English default: require the prop when closable, warn in dev if missing). Close control must not nest a pressable inside the tab pressable on web (sibling layout, see the nested-pressable rule from #565).
   - Closing the selected tab must move selection to the neighbour (previous, else next) and call onValueChange.
   - Optional `TabsList` `addon` slot (leading/trailing node) for a "+ new order" action.
2. #592 item 1 OTPInput segmented appearance: `appearance?: 'joined' | 'segmented'` (default joined, no behavior change). Segmented renders one visually separate box per digit with the same single hidden input contract, caret/focus indicator on the active cell, error/disabled states, RTL order correct, and Dynamic Type not clipping. Reuse existing tokens only.
3. #603 item 1 per-table row density with a 48 step: add the missing density step to the tokens scale (follow how the existing 44/56/64 row heights are defined in packages/tokens; run `pnpm tokens:generate && pnpm tokens:check && pnpm tokens:test`), then `Table density?: 'compact' | 'default' | 'comfortable' | 'dense48'` (pick names consistent with the existing density vocabulary; if the existing scale is compact/default/comfortable, add the 48 step as a named token and expose it) that overrides the global density for that table only. Existing tables unchanged.
4. #611 item 1 toolbar overflow primitive: new `Toolbar` + `ToolbarItem` (+ `ToolbarOverflowMenu` internal). Single-row toolbar that measures its children (onLayout) and moves items that do not fit into a trailing overflow DropdownMenu, in order of a `priority` prop (lower priority collapses first; items without priority never collapse). Keyboard and a11y: role toolbar, arrow-key roving focus on web, overflow trigger with aria-haspopup=menu; collapsed items keep their onPress/label/icon in the menu. No new dependencies. Provide a showcase example and tests for: all fit → no menu; narrow → lowest priority collapses first; resize restores.
