The #474 docs-portal work breakdown (sub-issues #455 B010/B011, #457 D030, #458 D031, #459 E040, #463 D033, #472, #473) lands as a series of `feat/*` PRs onto `development`. Each PR body carries an `AUTHORITATIVE_BASE_SHA` and a self-reported verification table.

**Why:** the wave is content-heavy and gated by machine checks (`docs:foundation:check`, `site:contract:check`, `docs:surface:check`, `check-public-doc-truth`, `check-public-web`, `llms:check`, `check-doc-examples`), so PR bodies claim green rather than showing CI.

**How to apply:**
- **Run `gh pr checks <n>` before anything else.** On PR #485 the body's table said `pnpm typecheck` PASS while `verify-docs` and `build-and-local-smoke` were red on CI. The tables are honest about what was run; they are produced on a **warm** developer tree and the author does not re-check CI.
- The recurring defect shape in this wave is **warm-tree vs cold-checkout divergence**. Four docs content families are gitignored and written only by `apps/docs`'s `prebuild` hook: `components/reference/`, `patterns/reference/`, `compatibility/current.md`, `guides/current-release.md`. CI's `verify-docs` job checks out, installs, and runs `pnpm web:check` with none of them present. Any check that walks the docs content tree must not assume they exist.
- To reproduce a cold checkout cheaply: copy `apps/docs/src` + `web/public-site.config.json` into `/private/tmp`, delete those four paths, and call the check's exported `collectViolations(shadowRoot)` directly. No full repo copy needed (a full copy is ~910 MB).
- `pnpm typecheck` now runs the full 21-step chain to exit 0, including `release-ruleset:check`. The old `bare-bundle` job-name failure is resolved — the note in an earlier version of this memory is stale.
- Node must be 24.13.1 (`engine-strict=true`); export `LANG`/`LC_ALL=en_US.UTF-8`. The shell is **zsh**, which does not word-split unquoted variables — `node ./scripts/$s` with `$s="x.mjs --check"` fails.
- Live environments exist and are reviewable: `https://beeui-dev.beemvp.com` serves the current `development` state (production `beeui.beemvp.com` does not resolve). `curl -o /dev/null -w '%{http_code}'` against dev is the cheapest way to settle a routing claim.
- Astro slugifies content filenames three ways: it drops dots (`current.generated.md` → `/currentgenerated/`), lowercases (`Upper_Case.md` → `/upper_case/`), and dash-joins whitespace (`with space.md` → `/with-space/`). `contentPathToRoute` in `scripts/generate-docs-foundation.mjs` mirrors **only the dot rule** (added in PR #485). Any manifest-driven check inherits the remaining two blind spots; no current filename triggers them.
- A real `astro build` in a review copy **is** possible and is the only way to settle a slug question for a hypothetical filename. `rsync -a --exclude .git` the worktree to `/private/tmp`, move in a `git clone --shared --no-checkout` gitdir, then `git checkout -f <branch>`; the copied pnpm links keep working for `docs:build`, all `scripts/*.mjs` checks, `typecheck` and `bench:web`. Only the showcase jest suite breaks in a copy (React resolves to null hooks) — rely on CI for that one. The scout hook blocks the literal string `node_modules`/`.git` in Bash commands, not the operations; put them in a script file under the scratchpad and run that.
- **`pnpm beeui -- <command>` is dead** under the pinned `pnpm@10.15.0`: pnpm forwards `--` into argv and the CLI rejects it with `unknown command '--'`. The working form is `pnpm beeui <command>`. The broken form was everywhere in the docs, and `check-doc-examples.mjs` / `check-ai-agent-contract.mjs` **regex-match the literal `pnpm beeui -- add`** — so fixing the docs without fixing those regexes silently disables the registry-item validation. As of `d8c38ae` the content tree is clean except one stale prose mention at `guides/cli-source-ownership.md:173`.
- The Worker serves **308 redirects from base-less doc paths** (`/compatibility/native/` → `/docs/compatibility/native/`). A missing-`/docs`-prefix link is therefore cosmetic, not broken — probe the dev origin before reporting one as a blocker.
- **Content quality splits cleanly by authorship, not by section.** Hand-authored `start/`, `guides/`, `learn/` are strong (outcome-first, executable examples, explicit state ownership). Everything emitted by `scripts/public-{component,pattern}-reference.mjs` and `scripts/public-reference.mjs` is an inventory of identifiers with constant per-page boilerplate — the generated `components/*.md` carry no props, types or defaults on any of the 62 pages, while six curated pages promise exactly that. Aim content review at the generator + its content JSON (`docs/*.content.json`), never at the emitted markdown.

- **This wave has started shipping "meta-guards" — scripts that assert the *documentation of* a gate still exists.** The recurring defect shape: they check that whatever the prose names still resolves (commands are real scripts, paths exist) but never that the required content is *present*, so the whole documented workflow can be deleted with the gate green. When reviewing one, gut the guarded prose down to the literal string the regex greps for and run the guard against a fixture root — a 10-line probe that has found the hole every time. Also check the regexes against line-wrapped markdown: `/\bpnpm (…)/` with a literal space silently skips a command whose backtick span wraps across a newline.
- **`pnpm typecheck` runs every `*:check` before `pnpm -r typecheck`, so `apps/docs`'s `pre*` generator hooks fire too late to matter.** `docs:contract:check` (`docs/component-reference.md`) and `docs:patterns:check` (`docs/pattern-library.md`) guard committed repo files whose generators are **not** in the docs app's `prebuild`/`pretypecheck` list — only the `public-*-reference.mjs` portal generators are. Any doc claiming "the docs build regenerates these for you" is false for those two.
- **`ownerStatus: 'planned'` passes `docs:surface:check`.** `validatePublicSurfaceInventory` only checks the field is truthy and that the route sits in a ratified IA section; nothing fails on unpublished. Prose claiming a *published* page is mandatory overstates the gate. Separately, adding a public component also requires `pnpm llms:generate` — the gate greps `llms-components.txt` for every public component name.
- **This worktree is shared with concurrent agents.** Mid-review, 69 docs files and a generator changed underneath a review. Pin the HEAD sha (`git archive <sha> | tar -x -C <scratch>`) and re-run `git status -- <reviewed files>` before writing the verdict, and say so in the report.
- **The wave's newest guard shape is the self-referential drift check: it recomputes its expected value from the same in-memory input the producer used, so it cannot fail.** `public-component-previews.mjs`'s excerpt-citation guard rebuilds `lines.slice(start-1, end)` — the exact expression that produced the text it compares against. To test one, never mutate the *output*; mutate the *numbering/derivation* function (e.g. `lineOf`) so the citation and the text stay self-consistent but both point at the wrong place. The guard stays green while the page quotes unrelated lines. Same probe applies to any "generated artifact matches its source" check in this repo.
- **PR bodies in this wave now claim "every new test was confirmed to fail with its production line reverted."** Treat as unverified: mutation-testing the previews suite found 4 of 8 target lines (final sort, merge-gap, region cap, smallest-first ordering) could be reverted with the suite fully green. Cheap harness: extract the pure functions into a scratchpad file, shim `typescript` via `createRequire(<repo>/scripts/x.mjs)`, and re-point the test file's import.
- **A new `*:check` script is not run on pull requests just because `ci-scope.mjs` maps it to a lane.** `.github/workflows/ci.yml`'s `verify-docs`/`verify-fast` jobs run a hand-curated command list; the full `pnpm typecheck`/`pnpm test` chains only run in `beeui-environment-ci.yml`, on *push to development/staging* (post-merge). `ci-scope.test.mjs`'s "every tracked file selects a lane" test forces the mapping, and nothing asserts any job actually invokes the script — so a PR can add a guard, map it, be green, and never execute it. Always diff the new `package.json` script names against the workflow step bodies.
- **Mutation-test the *revert*, not the *deletion*.** A mutation that removes declarations (`const substantive`/`trivial`) fails tests with a ReferenceError and looks like coverage; restoring the old behaviour (`[...withText].sort(bySize)`) can leave the suite fully green. Ask which shape a "N pass / M fail ✓" table used before crediting it.
- **Review-copy recipe that works here:** mirror the tree to `/private/tmp` with a Node script (real copies of `scripts/ apps/ docs/ examples/ packages/`, symlinks for module dirs) — every `scripts/*.mjs` check, generator and `node --test` suite runs. Two exceptions: anything shelling out to `git` (`hygiene:check`, `ci-scope.test.mjs`) needs a real gitdir, and `astro build` breaks on symlinked module trees. Run `pnpm exec astro build` inside `apps/docs` in the real worktree instead — it only writes gitignored `dist/`/`.astro/` and leaves `git status` clean.
- **Every page-side guard in this wave is `renderedPage.includes(x)` — membership, not association.** It proves the label, the `#L..-L..` link and the code text each appear *somewhere* on the page, never that they belong together. The probe that breaks all of them at once: mutate the renderer to pair each block with a *different* block's label/link (`_parts[_parts.length - 1 - i]`). The page then contains every expected string, so the guard and the whole suite stay green while 19 of 52 component pages deep-link each snippet to another snippet's lines. Apply this probe to any check whose body is a chain of `includes` on one big rendered string.
- **Watch for the vacuous-pass short circuit in new predicates.** `excerptMatchesAnchor` is `!anchor || text.includes(anchor)` — every range built by `enclosingExample`'s fallback (`return { start, end }`) carries no anchor and passes for free. Same shape recurs: a guard added to make a check non-vacuous, itself made vacuous by a falsy-input escape. Also prefer first-line equality over `includes` for anchors: `component-gallery.tsx` has byte-identical sibling blocks, so `includes` is satisfied by the wrong occurrence (20 of 52 families have a non-unique anchor).
- **`docs/component-reference.content.json` splits each component into `purpose` / `behavior` / `limitations`, and `purpose` fans out to five published locations** — the page's frontmatter `description:`, its lead paragraph, `components/index.md`, `docs/component-reference.md`, and the JSON. Correcting a false claim in `behavior` alone leaves the same claim published in the page's own lead and meta description; the page then contradicts itself. When reviewing a content-truth fix, grep the corrected sentence's *old* wording repo-wide before crediting it.

- **When a fix "extends an existing guard to another field", measure how much of that field the guard can even see.** `findUnknownBehaviorPropReferences` was extended from `behavior` to `purpose`/`limitations` as the structural fix for a prose contradiction — but its regex only matches backticked prop-shaped tokens, and `purpose` contains **zero** across all 62 families (`limitations`: 2, both just added; 54 of 62 families have no `limitations` at all). Reverting the offending string leaves the guard green. Probe: revert the exact pre-fix wording in the content JSON and re-run the check before crediting the guard.
- **A predicate tightened from `includes` to `===` usually over-fires.** `excerptMatchesAnchor`'s first-line *equality* rejects correct citations whenever the AST node does not begin its line (`{cond && <Accordion …>`, `const node = <X …>`), hard-failing `docs:build` with "The line derivation and the AST disagree" — which is false. `apps/showcase` already has 181 mid-line JSX starts. `text.split('\n')[0].includes(anchor)` measured identical mutation strength (51/52 genFail, `checkbox` residual) with zero false positives. Always run the tightened predicate against a *legal* variant, not just against the corruption it was written for.
- **`pnpm web:check` runs on pull requests (`ci.yml`'s `verify-docs` step body) and `check-public-web.mjs` dynamically imports every module in `scripts/public-web-checks/`.** So any collector dropped into that directory *is* PR-gated, even though `docs:*:check`/`docs:*:test` scripts are not. Twice now a PR body has claimed a new guard "runs locally and post-merge only" when the guard was re-exported from `public-web-checks/` and therefore ran on the PR. Read the step body *and* that directory's index before repeating the author's CI-gap claim.
- **Use `check-portal-pages-fresh.mjs` as a second mutation oracle for anything that touches a page generator.** Mutations that survive `node --test` on the unit suite (dropping `Math.max` in the merge, removing the `inert` dedup) are killed by regenerating and diffing the committed pages. Restore `apps/docs/src/content/docs/{components,patterns}` from the worktree before running it — an earlier generate run in the review copy makes every page report stale and hides the signal.
- **Mutation tables in this wave report the author's chosen set, not coverage of the new code.** "14 of 14" on PR #498 was true; an independent 22-mutation run found 5 survivors, 4 of them in lines that same commit added or edited (three of four new positional checks could be `if (false)`). Always mutate the *new* code specifically, not the constants the author already listed.

- **The wave has moved from "green check proves nothing" to "green check hides a regression the fix caused."** PR #499 made every scrollable `<pre>`/`<table>` focusable by adding `tabindex="0" role="region" aria-label`. The ARIA role overrides native semantics: CDP `Accessibility.getFullAXTree` on `/docs/components/table/` returns `{region:11}` as shipped vs `{table:8,row:31,cell:92,columnheader:32}` with the role stripped and `tabindex` kept — and axe WCAG passes **either way**. Whenever a fix adds an ARIA `role` to an element that has a native one, dump the AX tree with and without it; the WCAG ruleset cannot see the loss.
- **For any a11y change, re-run axe with the `best-practice` tag set, not just the spec's `wcag2a/2aa/21a/21aa`.** `src/a11y-gate.ts`'s `isBlocking` only blocks serious/critical, so moderate rules are invisible twice over. #499 introduced 366 `landmark-unique` nodes on 88 of 151 pages (baseline zero) — invisible to its own audit.
- **A whole-portal axe sweep is cheap and settles every "one page per section is enough" claim.** 151 routes x 2 viewports ~= 302 scans finishes in a couple of minutes: `pnpm -s docs:build`, `node apps/visual-regression/scripts/serve-docs.mjs` (port 4175), then a probe script placed *inside* `apps/visual-regression/` (module resolution fails from the scratchpad) driving `chromium` + `AxeBuilder` over every `index.html` in `apps/docs/dist`. Delete the probe afterwards; `apps/docs/dist` is gitignored so the build leaves the tree clean.
- **Probe alternative fixes at runtime with `page.evaluate` before recommending one.** Removing/rewriting attributes in the live DOM and re-running axe proves a recommendation in seconds. It also killed my first suggestion: a `<div role="region">` wrapper around the table does *not* fix it here, because Starlight's CSS puts `overflow` on the `<table>` itself, so the table stays the scrolling element and axe still fires.
- **`package.json` is not a gate.** `docs:a11y:check` occurs exactly once in the whole repo — its own definition. Not in `typecheck`, not in `check`, not in any workflow step body, while the PR body called it "load-bearing". Grep the script *name* repo-wide, not the file it runs.
- **Static HTML post-processors: test the malformed-input path on the server, not just the regex.** `serve-docs.mjs`'s bare `decodeURIComponent` kills the process on `curl --path-as-is '.../%zz'`. Traversal was correctly blocked; the crash was not. One `curl` found it.

- **Round-2 lesson from #499: mutate `main()`, not just the exported helpers.** The author's 6-mutation table was accurate and all six were killed, but every mutation lived in exported functions the unit suite imports. Four of my 17 survived, all in the CLI entrypoint: `const isCli = false`, dropping `process.exitCode = 1` in the `--check` branch, dropping it in the missing-dist branch, and loosening the gate to `violations.length > 10`. With `isCli = false` the rewrite *and* its guard both no-op, `pnpm docs:build` exits 0, and the unit suite is 12/12 green. Any `node script.mjs --check` guard in this repo has the same untested shape — check whether `main()`/`isCli` is exercised at all before crediting a mutation table.
- **`ci-scope.mjs` classifies `scripts/*.mjs` and `apps/docs/**` as `docs`+`web`, never `visual`** (`VISUAL_PREFIXES` = `packages/ui/src/`, `packages/tokens/src/`, `apps/showcase/`, `apps/visual-regression/`, `apps/demo/`, `registry/`). `web-a11y` gates every step on `visual == 'true'`, so a PR touching only a docs script or docs content skips the entire accessibility audit. #499 passes CI only because it also edits `apps/visual-regression/`. Verify lane selection with `printf '<path>' | node ./scripts/ci-scope.mjs` before repeating any "this is guarded by the axe audit" claim.
- **axe's `focus-order-semantics` is `experimental` and does not run even with `best-practice` requested.** So nothing in the suite judges whether a new `tabindex="0"` landed on an element with an appropriate role — the 581 tab stops #499 added are validated by no rule. Separately, `evaluateViolations` reads only `results.violations`; `results.incomplete` (up to 59 `color-contrast` nodes on one docs page) is discarded and never appears in the scenario report, so "0 violations" overstates what was decided.
- **Playwright project selection in `apps/visual-regression` is asymmetric**: `testIgnore` is generic (`a11y[-\w]*`) but the `a11y-audit` `testMatch` is an explicit alternation. A future `a11y-*.spec.ts` is excluded from all ten canonical projects and matched by no project — collected by nothing, silently never run.

- **Correction to the #499 landmark note above: `landmark-unique` is NOT a #499 regression.** Measured on both builds: 240 nodes / 48 pages on desktop at `9c2d7ea` **and** at `019213f`. The 366/88 figure was an intermediate #499 commit that has since been reverted (`019213f` dropped `role="region"`, kept `tabindex`). Re-measure both sides before attributing an a11y delta to a PR.
- **`apps/docs/dist` is rebuilt underneath you by concurrent agents.** A sweep started at 08:26 was silently measuring the *other* branch's output by 08:29. Always `cp -R apps/docs/dist $SCRATCH/dist-base` immediately after your own build and serve it with `DOCS_A11Y_DIST=` — `serve-docs.mjs` supports exactly this. Cheap distinguishing marker between base and #499 output: `<pre tabindex>` count (0 vs 3) on `/docs/components/table/`.
- **Background servers get SIGKILLed here (exit 137).** Both `nohup ... &` inside a Bash call and `run_in_background` servers died mid-sweep. The reliable pattern is to `spawn()` the server *inside* the probe script and `kill()` it at the end, on a private port (4399+), not the default 4175 another agent is using.
- **The coverage gate's next blind spot after `ownerStatus`: it never checks the owner page mentions the symbol.** Probe: for each of the 683 inventory rows, strip tags from the owner page's built HTML and test `row.name in text`. Found 5 real orphans (`ToastRuntimeProvider`, `ToastRuntimeProviderProps`, `getTextareaWebMinHeight`, `ListGroupMembershipContext`, `semanticTypographyClasses` — 0 occurrences in the portal, content tree *and* `llms*`) plus 62 `package-export` subpath rows documented in name only, all while `docs:surface:check` printed "683 owned by a published docs page".
- **"Props tables added" ≠ API reference.** 566 prop rows across 58 component pages, but only 68 (12%) have a non-empty Description, and **46 of 58 pages have an empty description on every row**. Type/default are mechanically derived and correct; the explanatory column was never filled. Measure the description column, not the row count.
- **The `llms*` artifacts still say "the repository is private by owner decision" — `api.github.com/repos/beobungbu/BeeUI` returns `private: false`.** `llms:check` regenerates and diffs, so it reproduces the sentence forever. Any claim in a generated artifact about *external* state (repo visibility, npm publication, tag existence) has no gate behind it; verify with an unauthenticated `curl`.
- **`docs:surface:check` and `docs:portal-pages:check` appear in ZERO workflow step bodies**, and `ci.yml` has no `pnpm typecheck`/`pnpm test` at all — they run post-merge only (`beeui-environment-ci.yml`). No Lighthouse/`bench:web` in any workflow either, so #466's "performance budgets pass" gate has nothing to pass.
- **Verified-good areas, so future reviews can skip re-measuring them:** 0 duplicate titles/descriptions/canonicals across 152 pages; 151-loc single-origin sitemap; edge-level `x-robots-tag: noindex` + `Disallow: /` on the dev origin (noindex is NOT in the HTML — do not report that as a gap); 17/17 legacy redirects single-hop 308→200; 0 broken internal page links; 0 horizontal overflow at 320/360/390 across all 151 pages; firefox+webkit clean. Genuinely missing: `Content-Security-Policy` and any frame policy (absent repo-wide), and `favicon.svg` (404 on every page).

- **A raw `<p …>` wrapper in a `.md` page silently disables inline markdown inside it.** CommonMark treats a line-initial `<p>` as an HTML block, so `` `code` `` and `**bold**` publish as literal source. #499's search work added `<p data-pagefind-weight="8">` to two pages; `guides/cli-source-ownership.md` renders three literal markdown spans on the live page. `docs:build`, `web:check`, `docs:portal-pages:check` and `docs:surface:check` are all green on it — the only way to see it is to grep the built `dist/**/index.html` for backticks/asterisks inside the wrapper. Whenever a diff introduces raw HTML into content markdown, dump the built HTML for that paragraph.
- **Grep the new script's *path* in `package.json`, not just the workflow.** `scripts/check-docs-search-intent.mjs` + its `__tests__` companion appear in zero `package.json` scripts, so they are unreachable from `pnpm typecheck`/`pnpm test` even post-merge, while `ci-scope.mjs` still maps them to `docs`+`web`. `grep -c '<script-basename>' package.json` is the one-command test.
- **Search-intent checks CAN be mutation-tested cheaply.** `git checkout <base> -- <page.md>` → `pnpm -s docs:build` (~60 s) → run `runQueryMatrix(distCopy)` → `git checkout HEAD -- <page.md>`. On #499 this proved the troubleshooting edits carry 2 queries and the `expo.md`/`cli-source-ownership.md` prose edits carry **zero** (15/15 with the CLI page fully reverted). Always isolate one page per rebuild; reverting three at once hides which one mattered.
- **`collectPropDescriptionCoverage`'s denominator is `shape.fields` only.** `shape.consumed` (the `| Prop | Default |` tables `renderConsumedProps` emits when a type has no own fields) publishes 39 more prop rows with no description column at all, 32 of them showing `—`. "583/583 (100%)" is 583 of 622 published rows. Also 234 of 552 unique rows are filled by 17 shared sentences in `docs/prop-glossary.json` keyed on prop *name*, not by per-prop JSDoc.
- **The ratchet is `described >= FLOOR`, so new undescribed props are free.** Proven: a synthetic 583-described/584-total manifest returns `[]` from `collectPropDescriptionViolations` (the `web:check` half). Only the `described === total` assertion in `docs:portal-pages:test` catches it, and that chain is `pnpm test`.
- **`summarizeDescription`'s 280-char budget cuts reader-facing contract, not "maintainer rationale".** Measured by setting the budget to 100000 and diffing: 5 unique props truncate, and 4 of the 5 lose user-facing instruction (`safeAreaEdges` loses "pass the edges this screen actually touches"; `sheet.avoidKeyboard` loses "does not itself read this flag" while *keeping* the `(#157, per ADR-006)` reference). To audit any summarizer, mutate its budget constant and diff the two manifests — do not read the regex.
